대안: signal 1건 push 후 N분 (예: 15분) 동안 동일 ticker 추가 push 보류 → 사용자 fatigue 완화. 또는 시간당 ≥ 5건 시 묶음 카드 1건 (summary digest) 으로 합치기.

**왜 지금**: 15분 polling 가동 후 24-48h 모니터링하며 burst 발생 빈도 측정. burst 0건이면 spec out, ≥ 1건이면 guardrail 본 sprint 채택.

**도입 비용**: `scripts/generate-whale-analysis.js` 1 파일 + state 파일 `.telegram-push-state.json` (gitignored) 또는 `whale-analyses.json` 의 `pushedAt` 필드. 약 30 LOC, 0.5 sprint.

**위험**: state 손실 시 (다음 polling) 같은 ticker 1회 추가 push — 캡 보호 (시간당 ≥ N 시 무조건 묶음) 으로 fail-safe.
