## 1. Telegram Bot API → 친구 초대 슬롯 (Viral wedge, W3)

**무엇**: Telegram bot `/invite` 명령으로 1-tap 공유 URL 발급 (개인별 referral 코드 포함). UTM `utm_source=telegram&utm_medium=invite&referral=<code>` 로 distribution 측정.

**왜 지금**: W3 의 distribution wedge 가 "blocked_real_users" 상태. 8명/일에서 30 WRSU 로 가는 사다리에 *바이럴 1.05x 계수* 가 가장 저렴함 (제품 변경 없이 채널 확장). 마일스톤 문서가 이미 명시 — "친구초대 슬롯".

**도입 비용**: 신규 endpoint (Supabase 또는 in-memory) + bot polling 핸들러 1개 + UTM 파서 확장. 1-1.5 sprint deliverable.

**위험**: spam 위험 (rate limit 필수). referral 보상 없을 시 클릭 동기 약함 → 첫 매출 이후 보상 설계.

## 2. SEC EDGAR Real-Time Filing Feed (Pull → Push, W1/W2 reliability)

**무엇**: SEC EDGAR 의 atom feed 가 아니라 `data.sec.gov/submissions/CIK*.json` 의 변경 감지 + Form 4 즉시 처리. 현재는 매일 07:00 KST cron — 16h 지연.

**왜 지금**: W3 "30초 안에 전달" 가설은 신속성에 달림. 16h 지연 = 다음날 새벽 통보 = 시장 반응 후. 동시에 W6 reliability — pull feed 가 누락된 alert 검출.

**도입 비용**: rate limit (10 req/s) + 변경 감지 캐시 (e.g. last seen accession#). cron 주기 단축이 90% 효용. 1 sprint.

**위험**: SEC 의 burst rate (10 req/s) 초과 시 IP 차단. 보수적 polling (15분 1회) 권장.
